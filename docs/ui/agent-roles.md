# UI 에이전트 역할 템플릿 (소집 가이드)

> UI 작업을 에이전트(또는 사람)에게 나눠 맡길 때 쓰는 표준 역할 정의. (collaboration-prd.md R5)
> 호출 시 각 역할의 "프롬프트" 블록을 그대로 복사해 쓴다. 모든 역할은 먼저 [`README.md`](README.md)를 읽는 것을 전제로 한다.

## 공통 전제 (모든 역할)

- 활성 코드베이스는 `signal-up`. 다른 폴더(`시그널 프로그램`)는 참조용.
- 색상·간격은 `app.css`의 `var(--token)`만 사용. 리터럴 색상 금지.
- 설정 폼의 `id` / `name` / `data-field` / `err-{field}` 속성은 디자인을 바꿔도 보존.
- 작업 후 `python scripts/ui_check.py`가 PASS여야 한다.

## 파일 충돌 규칙 (병렬 실행 시)

여러 역할을 동시에 돌릴 때, **같은 파일을 동시에 편집하면 충돌**한다. 안전한 분할:

| 동시 실행 가능 | 이유 |
|---------------|------|
| 토큰·CSS (`app.css`) ∥ 템플릿·구조 (`*.html`) | 파일이 겹치지 않음 |
| 탐색 ∥ (무엇이든) | 탐색은 읽기 전용 |
| 검증 ∥ (무엇이든) | 검증은 읽기 전용 |

**금지**: 토큰·CSS 역할 2개를 동시에 `app.css`에 → 같은 파일 동시 편집. 순차로 돌릴 것.

---

## 역할 1. 탐색 (Explorer) — 읽기 전용

- **입력**: 조사할 질문 (예: "특정 색상/클래스가 어디서 쓰이는지", "영향 범위")
- **산출**: 파일 경로 + 위치 + 핵심 스니펫 요약. 코드 변경 없음.
- **금지**: 어떤 파일도 수정하지 않음.
- **프롬프트**:
  > `signal-up`의 UI 코드에서 [질문]을 조사해줘. `docs/ui/README.md`의 파일맵을 기준으로, 정확한 절대경로·위치·핵심 스니펫만 요약하고 코드는 수정하지 마. 어느 게 활성 코드인지도 판단해줘.

## 역할 2. 토큰·CSS (Tokens/CSS)

- **입력**: 색상·간격·컴포넌트 스타일 변경 요청
- **산출**: `app.css` 수정. 토큰 변경 또는 컴포넌트 규칙 추가.
- **금지**: 템플릿(`*.html`) 구조 변경, 리터럴 색상 도입, 기존 클래스 중복 정의.
- **프롬프트**:
  > `app.css`만 수정해서 [변경]을 적용해줘. 새 색상은 반드시 `:root`/`[data-theme]`의 토큰으로 추가하고 컴포넌트는 `var(--token)`을 참조해. 기존 클래스를 중복 정의하지 말고, 끝나면 `python scripts/ui_check.py`로 B(중복)·C(하드코딩) 결과를 확인해줘. 템플릿 파일은 건드리지 마.

## 역할 3. 템플릿·구조 (Templates)

- **입력**: 레이아웃·마크업·컴포넌트 배치 변경 요청
- **산출**: `templates/*.html` 수정.
- **금지**: `settings.js` 의존 속성(`id`/`name`/`data-field`/`err-`) 제거·변경, `app.css` 편집(필요 시 토큰·CSS 역할에 위임).
- **프롬프트**:
  > `templates/`의 [페이지]를 수정해서 [변경]을 적용해줘. 기존 CSS 클래스를 재사용하고, 새 클래스가 필요하면 어떤 스타일이 필요한지 명시만 해(직접 `app.css`는 수정하지 마). 설정 폼이면 `id`/`name`/`data-field`/`err-{field}` 속성을 그대로 보존해. 끝나면 Jinja2 렌더와 `python scripts/ui_check.py`를 확인해줘.

## 역할 4. 접근성 (A11y)

- **입력**: 대비·포커스·모션·키보드 내비 점검 요청
- **산출**: 위반 목록 + 최소 수정안 (대비비, `:focus-visible`, `prefers-reduced-motion`, aria 등)
- **금지**: 디자인 의도(매수=빨강 등)를 바꾸는 색상 변경.
- **프롬프트**:
  > `/_styleguide`와 주요 페이지를 기준으로 WCAG AA 관점에서 점검해줘. 대비비 미달, 포커스 표시 누락, 모션 처리, 키보드 접근성을 목록화하고 각 항목에 최소 수정안을 제시해. 색상 의미(매수=빨강/매도=파랑)는 유지.

## 역할 5. 검증 (Verifier) — 읽기 전용

- **입력**: 변경된 범위
- **산출**: `python scripts/ui_check.py` 결과 + Jinja2 렌더 + (선택) 스크린샷 비교. PASS/FAIL 판정.
- **금지**: 코드 수정 (문제 발견 시 보고만).
- **프롬프트**:
  > 방금 변경된 UI를 검증해줘. `python scripts/ui_check.py`를 돌려 A(클래스 매칭)·B(중복) 차단 위반이 없는지 확인하고, 영향받은 템플릿을 Jinja2로 렌더해 오류가 없는지 봐. 문제를 찾으면 수정하지 말고 위치와 원인만 보고해줘.

## 표준 분할 예시

"설정 화면을 카드형으로 바꾸고 색감도 정리" 요청 →

1. **탐색**: 현재 설정 화면 구조·관련 클래스 파악 (읽기)
2. **토큰·CSS**: `app.css`에 카드/색상 규칙 추가 — *순차 1*
3. **템플릿**: `settings.html` 구조를 카드형으로 — *2와 병렬 가능 (파일 다름)*
4. **검증**: `ui_check.py` + 렌더 (마지막)
