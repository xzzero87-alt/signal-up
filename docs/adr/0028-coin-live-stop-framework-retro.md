# ADR-0028: 코인 라이브 중단 — 게이트 실측 NO-GO, 전 시장 알림 중지 + 프레임 회고 착수

**Date**: 2026-07-09
**Status**: accepted
**Deciders**: xzzero87

## Context

ADR-0027 Decision 3의 실측 결과(`live_audit_session_2026-07-09_summary.md`, Cowork Evaluator 독립 재집계로 검증): 라이브 코인 전략 후보 v1(BB+CCI)·v3(fractal) 모두 **압도적 게이트 미달** — 18마켓 통과 0/18, 하위구간 양(+) 0/4, 샤프 중앙값 −1.23/−1.06, 누적 중앙값 −59.94%/−58.71%(B&H −69.73%). 부수 발견: 라이브 경로(run·serve 모두)는 `strategy_version` 설정을 읽지 않고 `BbCciStrategy`를 하드코딩(cli.py:194·413) — 라이브는 항상 v1이었다. Windows 서비스 미등록·실행 중 프로세스 없음도 확인됨. 이로써 KR(ADR-0026)·코인 모두에서 게이트 통과 전략이 전무하다.

## Decision

1. **코인 라이브 알림을 중단한다.** ADR-0022 규율("게이트 미달 전략 라이브 금지")의 일관 적용 — KR(ADR-0026)과 동일. 현재 실행 중인 프로세스가 없으므로 실질 조치는 **재기동 금지**: 게이트 통과 전략이 나오기 전까지 `signal run`/`signal serve`의 라이브 루프를 운용 목적으로 기동하지 않는다.
2. **제품은 전 시장 알림 중단 상태로 전환한다** (KR: ADR-0026, 코인: 본 ADR). 백테스트·GUI·데이터 파이프라인 등 비라이브 기능은 유지.
3. **다음 안건은 게이트·제품 목적 회고다** (별도 세션·별도 ADR). 전 전략(v1~v5·kr_fractal)·전 시장(KR·코인)·전 조건 실패는 개별 전략의 실패가 아니라 시스템적 결과 — 새 전략 탐색 전에 프레임부터 재점검한다: (a) 게이트 기준(절대 B&H 초과)이 알림 제품 목적에 맞는가, (b) 제품 목표 재정의(엣지 알림 vs 방어/리스크 알림 vs 정보 대시보드), (c) 타임프레임·유니버스 적합성. 이 회고는 특정 전략 구제를 위한 사후 완화가 아니라 실측 완료 후의 프레임 재점검이다(ADR-0027 Risks에 예고).
4. **코드 정리 백로그를 기록하되 회고 이후 착수한다**: strategy_version 라이브 미배선(cli.py:194·413), 설정 소스 이원화(run=.env/serve=settings.json), fetch 클라이언트 무한루프. 제품 방향이 정해져야 어느 배선이 맞는 배선인지 결정 가능.

## Alternatives Considered

### Alternative 1: 코인 라이브 유지
- **Why not**: 실측 NO-GO 확정 후 유지는 규율 포기. "B&H보다 덜 잃음"(−59.9% vs −69.7%)은 샤프 −1.23의 하락장 상대 방어일 뿐 엣지가 아님.

### Alternative 2: 회고 없이 즉시 신규 전략 탐색
- **Why not**: 카탈로그 6종 × 2시장 × 정정 조건에서 전멸 — 같은 프레임에서 7번째 전략을 뽑는 것은 반복 실패 패턴. 프레임 진단이 먼저.

## Consequences

### Positive
- 규율 완결: 모든 라이브가 동일 기준으로 검증·정리됨. 부풀려진 근거로 도는 알림 0개.
- 회고가 깨끗한 전제(전 실측 데이터 확보) 위에서 시작됨.

### Negative
- 제품이 당분간 알림 0개 — 존재 이유가 회고 결과에 걸림.

### Risks
- 회고가 "게이트 완화"로 흐를 위험 — 회고 ADR에서 기준 변경 시 반드시 변경 사유가 특정 전략 구제와 독립적임을 입증할 것.
